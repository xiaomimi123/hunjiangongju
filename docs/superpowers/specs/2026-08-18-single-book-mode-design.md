# 单本书成片：口播只讲一本，书封快闪仍多本且以主题书收尾 设计

> 状态：已实现 · 2026-08-18 · 分支 feat/single-book
> 目标：学员填一个书名，成片从头到尾只讲这一本；开场快闪仍连闪多本书封，最后一张定格在主题书。

---

## 一、触发

用户看过 `final (1).mp4`（40.97s）后指出：文案讲了 4 本书（被讨厌的勇气 / 原子习惯 / 终身成长 / 心流），而产品要的是「填《被讨厌的勇气》，就只讲《被讨厌的勇气》」。

同一条片子确认了上一批的修复有效：4 个《书名》头与各自口播内容逐段吻合，未再出现错位。本设计不改动那套机制，只改「讲几本」。

**这是产品形态的推翻**：本会话早前确认过「AI 配齐到模板本数」，`select-books`、`BookLibrary`、后台书库页都是照此建的。用户已明确改为单本，并确认：

- 范围：**彻底换成单本**（学员/auto 路径）。
- 快闪：**仍多本书封连闪，最后一张是主题书**。
- 陪衬书来源：**先查书库，不够再联网**（`collectCandidates` 现状即如此，无需改）。
- 文案调性：**跟框架走**，不把「治愈系」写死在代码里。

## 二、关键区分：主题书 vs 陪衬书

| | 主题书 | 陪衬书 |
|---|---|---|
| 数量 | 恰好 1 本 | `__bookCount - 1` 本 |
| 来源 | 学员填的 `subject`，经查证补作者 | 书库同主题召回，不足再联网补 |
| 进口播 | 是，全篇只讲它 | **否，一句都不讲** |
| 进画面 | 是，快闪**最后一张**；正片《书名》头全程是它 | 是，快闪前几张 |
| 真实性要求 | 必须真实（书名+作者上屏） | 同样必须真实（书名+作者上屏） |

陪衬书虽不进口播，但书名与作者会显示在书封卡上，**不能是编造的**——所以现有的「书库召回 + 联网二次校验 + 沉淀」链路保留，只是它的产出改为纯视觉用途。

## 三、方案

### A `select-books`：主题书排到最后，并单独标出

`worker/src/gen/selectBooks.ts:323-328` 现在是 `books = [studentBook, ...picked]`（学员那本在首位）。改为 `books = [...picked, studentBook]`——快闪按 `variables.books` 顺序出卡，主题书排末位即「最后定格」。

同时把主题书单独写进 `variables.themeBook`（`{ title, author?, points? }`）。**它是下游判定「走单本文案」的唯一信号**：

- 写了 → `generateScript` 走单本路径。
- 没写 → 维持现有多本路径（运营手填书单、manual/imitate 文案模式、mock 兜底）。

之所以用 `themeBook` 而不是布尔开关：单本提示词需要书名/作者/要点，正文《书名》头也需要它，一个字段同时承担信号与数据，避免两处失配。

### B `generateScript`：单本文案路径

`variables.themeBook` 存在时，用新的 `buildSingleBookPrompt`：

- 只给这一本书的书名/作者/要点，不给书单。
- **硬性要求：全篇只讲这一本，严禁提及或引用任何其他书籍。** 这是本设计的核心约束，必须在提示词里显式写死——模型写书评时天然爱旁征博引别的书。
- 开场白沿用上一批的机制：模板是 flash 时把 `open.titleText` 喂进去，要求首段为「今天分享的是《书名》……」。画面标题与旁白呼应。
- 调性由 `frameworkText` 决定，不在代码里写死风格词。
- **不要求书序号标记**：全篇只有一本书，标记没有意义，多一条格式指令只会增加模型出错面。上一批的标记机制原样保留，供运营手填书单的多本路径继续使用。

《书名》头分配：单本路径下所有正文段一律用主题书，不走 `allocateBookIndexes`，也不走书序号标记。

### C `resolveBooks`：改为 `variables.books` 优先

`worker/src/gen/generateImage.ts:23-36` 现在是 `overlayTemplate.books` 优先、`variables.books` 回退。这是上一批终审记为「延后」的 Important 项，当时判定「无 UI 可达路径能同时触发」故未修；**本设计使它成为阻塞项**——快闪书封若取自框架自带书目，本次排好的「主题书末位」顺序会被整个绕开，主题书不会出现在最后一张，甚至可能完全不出现。

改为 `variables.books` 优先、`overlayTemplate.books` 回退。语义上也更正确：per-generation 的选择比框架模板自带的默认值更具体。框架自带书目退回它本来的定位——「原片信息，仅供参考」。

## 四、改动面

```
worker/src/gen/selectBooks.ts      ← 主题书排末位；写 variables.themeBook
worker/src/gen/generateScript.ts   ← 新增 buildSingleBookPrompt；单本路径；《书名》头全程主题书
worker/src/gen/generateImage.ts    ← resolveBooks 改为 variables.books 优先
```

不改渲染层、不改模板参数、不改数据库、不新增字段（`themeBook` 落在既有的 `variables` Json 里）。

## 五、错误处理

- 学员填的不是真书（查不到作者）→ 沿用现有三级兜底，作者留空仍作为主题书使用，不硬失败。**不因此退回多本模式**。
- 陪衬书一本都凑不到（书库空 + 联网失败）→ `variables.books` 只含主题书，快闪只有一张卡。口播不受影响。
- `themeBook` 缺失（老任务重跑、mock 兜底）→ 走原多本路径，零回归。
- 模型在单本文案里仍提到别的书 → 提示词硬性约束 + 上线后看真实成片。**不做自动检测与重写**（会引入误杀正常引用，如作者自述里提到自己另一本书）；先观察。

## 六、测试

- `selectBooks`：主题书位于 `variables.books` 末位；`variables.themeBook` 与末位那本一致；陪衬书数 = `__bookCount - 1`；`n=1` 时只有主题书且不调用候选池。
- `buildSingleBookPrompt`：含书名/作者/要点；含「只讲这一本、不得提及其他书籍」的硬约束；传 `openTitleText` 时含「今天分享的是《书名》」式开场要求；不含书序号格式要求。
- `generateScript` 集成：`themeBook` 存在 → 所有正文段 `bookTitle` 均为主题书，且发给 LLM 的 prompt 不含其他书名；`themeBook` 缺失 → 与今天行为一致（多本路径、书序号标记仍生效）。
- `resolveBooks`：`variables.books` 非空时优先于 `overlayTemplate.books`；`variables.books` 为空时回退框架书目；两者皆空 → 空数组。
- 回归：现有全部测试绿；运营手填书单、manual/imitate 三条路径行为不变。

## 七、风险与取舍

- **推翻既有产品形态**：`select-books` 的「配齐 N 本供口播」变成「配齐 N 本供快闪」。书库、后台书库页、联网查证全部保留且仍有用（陪衬书同样要真实），但它们的价值权重下降——陪衬书讲不讲得准，观众感知远不如主题书强。
- **模型可能仍旁征博引**：单本书评比多本更容易写着写着扯到别的书。只靠提示词约束，不做后处理。
- **陪衬书与主题的相关性下降**：改为书库优先后，陪衬书可能只是「同主题标签」的旧沉淀，不如每次联网检索贴合。这是用户明确选择的成本取舍（省调用、更快）。
- **快闪卡数 = `__bookCount`**：若某框架该值很大（如 13），需要凑 12 本陪衬书，书库不足时联网成本反而更高。上线后按真实框架值观察，必要时再给单本模式单独设一个更小的上限。

## 八、实现与设计的差异

方案 A/B/C 与「四、改动面」列出的三个文件均按设计原样落地（`worker/src/gen/selectBooks.ts:323-328` 的 `[studentBook, ...picked]` → `[...picked, studentBook]`、`themeBook` 写入、`buildSingleBookPrompt`、单本路径接线、`resolveBooks` 优先级反转，逐条核对提交 d733625 / 8962234 / 4d31291 / 5bce7c7 无出入）。以下四点是实现过程中偏离设计文字表述、或设计未预判到的地方，均已读实际 diff 核实：

1. **既有测试断言随「排末位」改动同步翻转，不是新增测试**：`selectBooks.test.ts` 里多条原本断言「学员书固定在 `books[0]`」的既有用例（规则 3、学员书作者三级兜底等），随 d733625 一并改为断言 `books[books.length - 1]`；这些用例的名字也从「排第一」改成「排末位」。语义仍是「学员书必出现且位置结构性固定」，只是位置从头换到尾——设计里没有单独提到需要动既有测试，实现时是必然联动的一部分。
2. **`resolveBooks` 优先级反转同样改写了一条既有用例**：`generateImage.covers.test.ts` 里原本断言「优先 `overlayTemplate.books`」的用例，随 8962234 直接改写为断言「优先 `variables.books`」（同一输入，期望输出从旧优先级的结果换成新优先级的结果），否则新旧断言会互相矛盾、无法同时通过。设计正文（方案 C）说明了要反转优先级，但没提到这会连带改一条现有断言。
3. **`selectBooks.ts` 里说反的「排第一」注释是终审阶段补的收尾，不属本设计原定范围**：770282a 更正了顶部硬约束 3 与 `collectCandidates` 函数上方两处仍写着「学员书排第一」的旧注释（与改后的排末位相反）。这段注释的作用是防止后人凭直觉「修正」代码——不改的话，后来者可能照着错误注释把代码「改回」排第一，等于复活已修复的 bug。这是代码质量收尾，不改变行为，设计文档本身未提及。
4. **mock 模式下 `themeBook` 同样会写入，比设计「五、错误处理」的表述更彻底**：设计原文把「mock 兜底」与「老任务重跑」并列为 `themeBook` 缺失、走原多本路径的场景之一。但实际实现（d733625 的 `writeBooksAndEnqueue` mock 分支）里，mock 模式同样把 `buildMockBookList` 固定排第一的学员书取出、挪到末位、并作为 `themeBook` 写入——mock 生成的任务因此也会进入 `generateScript` 的单本路径，行为与真实路径一致。本任务 Step 4 的端到端冒烟测试正是全程用 `isMockMode=true` 跑通 `selectBooks()→generateScript()`，验证了这一点（见 task-5-report.md）。设计文字需要以代码行为为准更正：`themeBook` 只在「运营手填书单 / `scriptMode` 非 `auto`」时缺失，mock 模式不在此列。
