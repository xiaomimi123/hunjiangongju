# 渲染引擎迁移到 FFmpeg 设计

> 状态：阶段 0 已完成 · 2026-08-20
> 目标：把「每条片子付一次」的渲染成本从 28.8 核·分钟压到 0.36 核·分钟，支撑每天上万条。

---

## 一、为什么必须迁移

| | 每条成本 | 1 万条/天所需 CPU |
|---|---|---|
| HyperFrames（现状） | 28.8 核·分钟 | **200 核，7×24 不停** |
| FFmpeg 直出（同规格实测） | 0.36 核·分钟 | **2.5 核** |

相差 **80 倍**。HyperFrames 是「把网页用无头 Chromium 逐帧截图」，97% 的时间花在浏览器绘制上，不是调参数能补的。

**HyperFrames 不废弃**，降级为「模板资产预渲染器」：每个模板只付一次的装饰动画（水波纹等）预渲染成带 alpha 的素材，每条片子只做 overlay。

## 二、能搬什么，不能搬什么

| 图层 | FFmpeg 方案 | 保真度 |
|---|---|---|
| 正片配图 + 推近运镜 | `zoompan` | 一样，照抄实测关键帧数值 |
| 逐边界转场（叠化/硬切） | `xfade` / `concat` | 一样 |
| 正文字幕 | ASS 烧字幕 | 一样 |
| 常驻《书名》大标题、水印 | ASS / `drawtext` | 一样 |
| 压暗底、暗角、颗粒 | 静态 PNG `overlay` | 一样 |
| 调色 | `eq` / `curves` | 一样 |
| 水滴水波纹 | 预渲染 alpha 素材 `overlay` | 一样（每条片子相同，一次性渲好复用） |
| 快闪书封 | `overlay` + `drawtext` 时间窗 | 基本一样，中文字号/描边需手工标定 |
| 字幕入场动画 | ASS `\fad \move \t` | **部分**，弹跳类缓动做不出 |
| **开场碎片** | 20 片 `crop`+`rotate`+`overlay` | **最不确定的一块**，见下 |

**开场碎片是唯一的硬骨头**：碎片带的是**这条片子自己的图**，不能像水波纹那样预渲染成固定素材。技术上可以给 20 个碎片各拉一条 `crop → rotate(c=none) → overlay(x,y 表达式)` 链，但这是整个迁移里最花时间、最不确定的部分。

**备选（混合方案）**：开场那 2.16 秒仍用 HyperFrames 渲，其余全走 FFmpeg。成本从 200 核降到约 **17 核**——比 2.5 核差，但立刻可用、风险低得多。

## 三、明确不做

- ~~逐像素折射类特效~~ —— **这条判断错了，已推翻**。ffmpeg 的 `displace` 滤镜就是按位移图
  逐像素推移，正是 `feDisplacementMap` 的等价物。水波纹现在是真折射（位移层 + 高光层），
  不再是「画一圈白环」的近似。做不到的只剩 3D 几何类效果（开场碎片的厚度与真实折射）。
- 字幕的弹跳缓动：ASS 的 `\t` 只能线性/幂次插值，`back.out` 这类过冲曲线无对应写法。

## 四、阶段 0（已完成）——先把盲区堵上

### 4.1 背景：一次「测试全绿但线上全坏」的事故

线上每条成片从约 2 秒起画面定格、正文字幕整条消失，而当时 **826 个单元测试全绿**。

根因：现有测试断言的是 `buildFfmpegArgs` 拼出来的**参数字符串**，那串字符串完全正确；错的是那个 ffmpeg 二进制**执行**它的行为（滤镜链里的 `zoompan`）。

**参数对 ≠ 画面对。** 迁移之后「整个产品就等于那张滤镜图」，这个盲区会从「一个装饰效果出错」放大成「每条片子的画面都可能静默出错」。所以阶段 0 不是额外开销，是迁移的前置条件。

### 4.2 ffmpeg 版本钉死（`worker/Dockerfile`）

原本 `apt-get install ffmpeg` 装到的是 Debian 12 自带的 `5.1.9-0+deb12u1`。

**注意结论边界**：没有证据表明那是「老版本的已知 bug」——用上游 5.1 与 7.1 的静态构建、喂同样的 HyperFrames 输出（`time_base 1/15360`、30fps CFR），两种滤镜写法都**复现不出来**。真正的问题是「发行版打过补丁的那个二进制行为不可控」，而不是「版本旧」。

改为**用 HTTPS 下载**固定版本静态二进制（`registry.npmmirror.com` 的 `ffmpeg-static` 二进制目录，
内容是 johnvansickle 的 ffmpeg 7.0.2 静态构建，`ffmpeg` 与 `ffprobe` 同目录）：

**为什么不从 Docker Hub 拉镜像**：服务器的镜像加速源只代理官方 `library/*`，
用户镜像（`mwader/static-ffmpeg` 之类）一律 **403 Forbidden**，构建直接失败。
走 HTTPS 下二进制与 npm 是同一条通路，已验证可达。

1. 版本写死在 `ARG FFMPEG_VERSION` 里，升级是一次显式改动，不随基础镜像漂移
2. **本地开发与服务器跑同一个二进制**，滤镜行为差异这个变量被彻底消掉
3. 静态构建自带 libass/freetype/fontconfig/x264，迁移所需滤镜齐全（已核验：`zoompan xfade overlay subtitles ass drawtext concat alphamerge rotate crop scale eq curves` + `libx264 aac`）
4. 构建期自检：版本或关键滤镜缺失直接构建失败

必须用「全局 ARG + 命名构建阶段」而非 `COPY --from=image:${ARG}`——本仓因中文路径必须 `DOCKER_BUILDKIT=0`，经典构建器不展开 `COPY --from` 里的变量镜像引用。

### 4.3 真渲验收测试（`worker/src/gen/renderVideo.e2e.test.ts`）

真的跑一遍 ffmpeg，断言**渲出来的像素与声音**：

- **画面全程在动**：八个时刻的帧指纹互不相同 → 任何定格都过不了（对应 zoompan 事故）
- **齿轮音落在快闪段**：`silencedetect` 的首个有声区间贴着开场结束点 → 对应「齿轮音被写成从 0 秒盖在开场上」那次事故
- **水滴音被截断**：有声区间长度 < 0.8s → 对应「1.595s 素材未截断、拖进正片第一句台词」
- 输出规格：720×960、带音轨

默认跳过（要真跑 ffmpeg、耗几秒 CPU）：

```bash
# 本地
RENDER_E2E=1 npx vitest run worker/src/gen/renderVideo.e2e.test.ts
# 权威口径：容器里的 ffmpeg 与生产是同一个钉死的二进制
docker compose run --rm worker npm run test:render -w worker
```

**一条必须记住的坑**：`frameHash` 里的 `-an` 不能省。`-f md5` 会把复用进容器的所有流一起哈希，成片带音轨、音频逐时刻不同，于是**哪怕画面完全冻结、指纹也各不相同**——「帧互不相同」那条断言会变成永远通过的假绿。这是用「故意造一段定格画面」验出来的，不是推理出来的。**改动取帧逻辑前，请先用定格输入确认断言仍会红。**

## 四·五、阶段 1（进行中）

### 已完成

- **正片视觉滤镜图**（`worker/src/render/ffmpeg/bodyGraph.ts`）：静图 → 预放大 → 运镜 → 逐边界转场。
  实测 4 段 / 19.6 秒 / 含 2 处叠化 + 3 段运镜 = **0.316 核·分钟/条**，1 万条/天仅需 **2.2 核**。
- **文字层**（`worker/src/render/ffmpeg/ass.ts`）：正文字幕 + 常驻《书名》+ 水印，全部收敛到一个 ASS 文件。

### 三个实测踩出来的坑（不是推理）

1. **运镜前必须预放大**：zoompan 在输入分辨率上按整数像素裁剪，直接对 720×960 做 1.0→1.1
   会有肉眼可见的抖动。预放大 2 倍后误差落在更细网格上。
2. **每一路都要归一化 `format/fps/settb`**：xfade 要求两路输入完全一致，否则报
   `Failed to configure output pad`。触发点是「前一路是 concat 输出」——单段直接接 xfade 不炸，
   所以只在「硬切后面跟叠化」的混排里出现，而客户样例恰恰是这种形态。
3. **ASS 三件套**：颜色是 `&HAABBGGRR`（BGR 反序 + alpha 前置且是**透明度**）；
   时间码是**百分秒两位**；`PlayResX/Y` 不设的话 libass 按 384×288 换算、字号整体缩水且不报错。

### 字体自带（原本的「尚未验证」项，已解决）

**曾经的问题**：ASS 的 Fontname 走系统 fontconfig 解析时，本机（macOS，无 Noto CJK）会退到
Helvetica，中文逐字回退失败、画出来是豆腐块——**而墨迹断言照样绿**。也就是说字幕对不对
取决于运行环境装了什么字体，本地根本无法验证，只能去服务器上做。

**解决**：把字体文件放进仓库（`worker/templates/booklist/fonts/NotoSansSC-Regular.otf`，
SIL Open Font License 1.1，允许随产品分发），渲染时用 `fontsdir` 指过去。
本地与服务器用同一个二进制字体，字体解析变成确定性的，**本地即可完整验收**。

实测 libass 日志：`fontselect: (Noto Sans SC, 400, 0) -> NotoSansSC-Regular` —— 解析到自带字体，
无缺字回退。那条字体校验断言因此不再需要环境开关，任何环境都必须绿。

只带 Regular，粗体由 libass 合成（大字号下观感可接受）；再带一个 Bold 面会让仓库多 8MB。

### 阶段 2（已完成）——快闪书封

结构与正片同源，视觉复用 `bodyGraph`；`flash.ts` 只管逐卡时长与文字排版。
`distributeCards` 按草稿逐卡时长的**比例**排进实际窗口，不等分（等分实测切点偏差最大 58.7ms）。
**弹入是近似**：原模板 0.86→1（由小变大），zoompan 缩放下界是 1、做不到，退化成 1.12→1。

### 阶段 4（已完成）——装饰层预渲染

水波纹是纯装饰，同一框架的每条片子长得一模一样。渲成一串带透明通道的 PNG 存起来
（实测 720×960 / 14 帧 / **1.5 秒**，一个模板只付一次），每条片子只做 overlay。
这是 HyperFrames 降级为「模板资产预渲染器」之后第一个真正落到该形态的效果。

用 `geq` 逐像素画同心圆环。geq 很慢，但这里不在乎——**绝对不能把 geq 放进逐条片子的滤镜链**。

### ⚠️ 度量方法上的两次修正（影响所有「画面在动」类断言）

1. **帧 md5 相同 ⇒ 定格** 这个推断**是错的**。它只在纯色画面成立：x264 在 crf 28 下逐帧
   调 QP，有纹理的静止画面也会给出不同 md5。实测一张 testsrc 花纹静图关掉运镜，
   6 个时刻取到 5 个不同 md5。**所有基于帧指纹的运镜断言，在运镜坏掉时照样会通过。**
2. 改用帧间平均绝对差仍不够：缓慢推近（1.0→1.108）相隔 1.5 秒只有 3.4，静止噪声是 3。
   两种变化的**分布**不同——噪声让几乎所有像素差 1~2，运镜让边缘像素差几十——平均值抹平了差别。

**最终指标**：变化幅度超过 12 的**像素占比**（`testkit.ts`）。实测标定：

| | 静止 | 运镜 |
|---|---|---|
| 0.5→2.0s | 0.0000 | 0.0938 |
| 0.5→5.0s | 0.0000 | 0.2498 |

且用**相邻采样**而非两两组合取最小——缓慢运镜下相距近的两帧本来差别就小。

## 五、后续阶段

| 阶段 | 内容 | 估时 |
|---|---|---|
| 1 | 正片段：运镜 + 转场 + ASS 字幕 + 标题 + 水印 + 调色（占片长 80%） | 1 天 |
| 2 | 快闪书封 | 0.5–1 天 |
| 3 | 开场碎片（可用混合方案跳过） | 1–2 天 |
| 4 | 装饰层预渲染（水波纹等） | 0.5 天 |
| 5 | 接线、灰度开关、保真度回归、跑批验收 | 1 天 |

全程新旧渲染器并存，框架上一个字段决定走哪条，出问题随时切回 HyperFrames，不断产。

**默认已翻成 ffmpeg**（`readRenderer`）。最初默认留在 HyperFrames 是为了「发版不改变存量框架的成片」，
实测下来这个保守默认代价更大：成本差 8 倍；而且开关只能写在 `overlayTemplate` 的 JSON 里，
后台编辑页保存时会把整个 `overlayTemplate` 覆写回去——用 SQL 设好的开关被一次「保存」抹掉过。
现在只有显式写 `"__renderer": "hyperframes"` 才退回旧渲染器。

**HyperFrames 没有删也不能删**：开场碎裂那 2.16 秒仍由它渲，碎片要带着本条片子自己的图，
ffmpeg 目前给不出来（阶段 3 未做）。开关切的是「正片+快闪走哪条路」，不是「用不用 HyperFrames」。

**每个阶段的验收口径**：新增的真渲断言必须先用「故意做错的输入」确认会红，再确认正确输入会绿。只看测试绿不算数——这正是本次事故的教训。
